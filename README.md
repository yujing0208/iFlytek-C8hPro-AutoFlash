## 为什么有这个项目

原教程的流程是「打开 spd_dump → 进 BROM → 粘贴 fdl → 粘贴 exec → 粘贴 `r all` → 粘贴 `w uboot` → …」，
命令多、路径写死、粘错一条就得重来；而且原文第三章的回锁部分是「代码此处不再赘述」。

这个项目把整条链路固化下来：

| 对比项 | 原教程（手动） | 本项目（自动化） |
| --- | --- | --- |
| 交互方式 | 手动逐条粘贴 10+ 条命令 | 双击脚本，按中文提示走 |
| 路径 | 写死 `C:\flash_tool\`，必须放对位置 | **全部相对路径**，整个文件夹拷到哪都能跑 |
| 提示语言 | 英文 / 无 | **全程中文**，每一步都告诉你该干什么 |
| 驱动 | 需要自己先装 | **自动检测，缺失则静默安装** |
| 依赖检查 | 无 | 刷写前逐个校验必需文件是否存在 |
| 回锁恢复 | 「此处不再赘述」 | 提供完整的回锁 + 恢复原厂脚本 |

## 三个脚本

| 脚本 | 作用 | 对应原教程章节 |
| --- | --- | --- |
| `1-解锁BL.bat` | 解锁 Bootloader | 一、解除 BL 锁 |
| `2-刷入GSI.bat` | 刷入第三方系统镜像 | 二、刷写 GSI |
| `3-回锁恢复.bat` | 回锁并恢复原厂系统 | 三、刷回原系统与回锁 BL 锁 |

## 目录结构

脚本用相对路径定位程序与镜像，所以**目录层级不能改**（整个 `Auto-flash` 文件夹可以随便移动）：

```
Auto-flash\
├── Driver_R4.21.3201\
│   └── Driver_R4.21.3201\DriversForWin10\   ← 紫光展锐驱动（DPInst64.exe 所在）
└── spd_dump_stable_250131\
    ├── SPRD\
    │   ├── spd_dump.exe                     ← 深刷工具
    │   └── _file\                           ← 所有镜像放这里
    │       ├── fdl1.bin  fdl2.bin
    │       ├── uboot_c8hpro_unlock.bin      ← 解锁用
    │       ├── splloader_c8hpro_disverify.bin
    │       ├── uboot.bin  splloader.bin     ← 原厂引导（回锁用）
    │       ├── boot.bin  system.bin  vendor.bin
    │       ├── vbmeta.bin  misc.bin  miscdata.bin
    │       └── system.img                   ← 要刷的 GSI
    └── 刷机自动化脚本\                       ← 本项目的 3 个脚本
        ├── 1-解锁BL.bat

```

镜像文件（`system.img` / `system.bin` 等）体积很大，不在本仓库内，请从 [原仓库](https://github.com/yujing0208/-c8hPro-) 或你自己的备份获取。

## 使用方法

1. 按上面的目录结构把文件放好（`spd_dump.exe`、驱动、镜像）。
2. 平板**完全关机**（最好长按电源键 15 秒强制断电）。
3. 双击 `1-解锁BL.bat`，按屏幕上的中文提示操作：
   - 脚本会先检查驱动，没装会自动静默安装（需要管理员权限，会弹 UAC，点「是」）；
   - 然后让你**长按音量减键不放**，把数据线插进电脑，等待设备接入；
   - 识别到设备后自动完成解锁并重启。
4. 刷系统：双击 `2-刷入GSI.bat`，同样按提示进 BROM。
5. 想回到原厂：双击 `3-回锁恢复.bat`，它会先把 8 个原厂分区写回、再回锁引导。

> 进入 BROM 的方法：**先把平板关机**，然后**按住音量减键不要松手**，再把 USB 数据线插到电脑上。
> 如果出现无限重启/黑屏，按住**音量减 + 电源键 15 秒**即可重新连上电脑。

## 编码说明

脚本是 **GBK(936)** 编码 —— 这是 Windows 的 cmd 正确显示中文提示的前提。

因此：

- 在 GitHub 网页上预览这些 `.bat`，中文会显示成乱码，**这是正常现象**，不是文件损坏；
- 本地用记事本 / VSCode 打开时，编码选择 **GBK / ANSI** 即可正常查看和编辑；
- **不要**把它转存成 UTF-8。cmd 会按 GBK 解码，转成 UTF-8 后中文提示会全部乱码（实测过 `chcp 65001` 方案，多字节行会导致批处理解析错乱，不可靠）。
